## 1.2.6 Actions to control ordering of steps in algorithms

Algorithms use control actions to manage the order in which steps are executed. These actions determine how instructions flow through a solution and how decisions and repetition are handled. :contentReference[oaicite:0]{index=0}

**Sequence**  

  Steps are executed one after another in a fixed order.  
  **Purpose:** to ensure instructions run in a defined progression from start to finish.  
  **Benefits:**  
  - simple and predictable execution  
  - easy to understand and trace  
  **Drawbacks:**  
  - limited flexibility  
  - cannot respond to changing conditions.

**Selection**  

  Different paths are chosen based on conditions.  
  **Purpose:** to allow decision making within an algorithm.  
  **Benefits:**  
  - supports conditional logic  
  - enables alternative outcomes  
  **Drawbacks:**  
  - increases complexity  
  - poorly structured conditions reduce readability.

**Iteration**  

  Steps are repeated while a condition is met or for a fixed number of times.  
  **Purpose:** to automate repetition of instructions.  
  **Benefits:**  
  - reduces duplicated code  
  - supports efficient processing of repeated tasks  
  **Drawbacks:**  
  - risk of infinite loops  
  - harder to trace execution flow.

## Exam Focus
You should be able to:
- Define sequence, selection and iteration
- Explain how each action controls algorithm flow
- Compare benefits and drawbacks of each action
- Identify control actions in algorithm representations
- Justify selection of control actions in given contexts

!!! tip "Exam tip"
    Questions may require explanation or justification of control actions. Responses should link sequence, selection and iteration to logical flow, decision making and repetition within algorithms.
