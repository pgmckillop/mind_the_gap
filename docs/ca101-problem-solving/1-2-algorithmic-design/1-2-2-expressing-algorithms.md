### 1.2.2 Ways algorithms can be expressed

Algorithms can be expressed in multiple forms to represent logic, sequence and structure in digital software development. Each method supports understanding, communication and implementation of solutions. :contentReference[oaicite:0]{index=0}

---

## Flowcharts

Flowcharts represent algorithms visually using standard symbols to show sequence, decisions and processing steps.

### Terminators

Indicate the start and end of an algorithm.

**Purpose:**  
to clearly define entry and exit points.

**Benefits:**

- improves clarity of algorithm boundaries  
- supports structured flow  

**Drawbacks:**

- adds visual elements that may be unnecessary for simple algorithms.

---

**Processes**  

Represent actions or calculations performed.  

**Purpose:** to show operational steps. 

**Benefits:**

- clearly identifies processing logic  
- supports step-by-step understanding  
  
**Drawbacks:**

- may become cluttered in complex algorithms.

---

**Sub-processes**  

Represent grouped actions or reused logic.  

**Purpose:** to reduce repetition and simplify diagrams.  

**Benefits:**

- improves organisation  
- supports modular design  
  
**Drawbacks:**

- hides internal detail  
- requires separate definition.

---

**Decisions**  

Represent conditional branching.  

**Purpose:** to control flow based on conditions.  

**Benefits:**

- clearly shows alternative paths  
- supports logical reasoning  
  
**Drawbacks:**

- multiple decisions increase complexity.

---

**Inputs/outputs**  

Represent data entering or leaving the algorithm.  

**Purpose:** to show interaction with users or data sources.  

**Benefits:**

- clarifies data flow  
- improves understanding of system interaction  

**Drawbacks:**

- limited detail on data structure.

---

**Arrows**  
Show direction of flow between symbols.  

**Purpose:** to indicate sequence of execution.  

**Benefits:**

- maintains logical order  
- improves readability  

**Drawbacks:**

- can become difficult to follow in large diagrams.

---

**Labels**  
Provide descriptions of actions or paths.  

**Purpose:** to clarify meaning of steps.  

**Benefits:**

- improves interpretation  
- reduces ambiguity  

**Drawbacks:**

- excessive labelling reduces visual clarity.

---

## Written descriptions using hierarchical markers

Written descriptions express algorithms using structured text and hierarchical markers to indicate sequence and grouping.

**Purpose:** to describe logic in a readable, ordered format.

**Benefits**

- accessible to non-technical audiences  
- flexible representation.

**Drawbacks**

- less precise than visual or coded representations  
- harder to validate logic flow.

---

## Code (commands in Appendix 2)

Algorithms can be expressed directly in code using programming commands.

**Purpose:** to provide executable representations of logic.

**Benefits**

- precise and unambiguous  
- directly implementable.

**Drawbacks**

- requires programming knowledge  
- less suitable for early design stages.

---

## Exam Focus  

You should be able to:

- Identify ways algorithms can be expressed
- Explain flowchart components and their purposes
- Interpret written algorithm descriptions
- Recognise algorithms represented in code
- Compare benefits and drawbacks of each representation method
- Justify suitability of representations for given contexts

!!! tip "Exam tip"
    Questions may require comparison of algorithm representations. Responses should reference flowchart elements, written descriptions and code, weighing clarity, precision and suitability for design or implementation.
